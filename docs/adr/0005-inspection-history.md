# ADR 0005 MySQL 검사 이력과 재전송 규칙

- 상태는 제안이다.
- 관련 단계는 S05다.
- 관련 요구사항은 F05와 F07이다.
- x64 독립 콘솔과 MySQL 8.4.13에서 저장, 충돌, 롤백, 연결 단절 및 커밋 응답 유실을 검증했다.

## 문제와 제약

검사 결과와 분석 시도는 함께 저장되어야 한다. 네트워크 문제로 저장 응답을 받지 못한 요청도 같은 ID로 다시 보낼 수 있어야 한다. 검사 판정과 저장 상태는 별도로 표시한다.

## 대안과 제안

한 테이블에 분석 내역을 JSON으로 넣으면 저장은 단순하지만, 분석 시도별 조회·순서 제약과 PRD의 분리 요구를 충족하기 어렵다. **InnoDB 검사 테이블과 분석 시도 테이블을 하나의 트랜잭션으로 저장**하는 안을 제안한다. 검사 테이블은 `inspection_id`를 기본키로, `request_id`를 고유키로 둔다. 시도 테이블은 검사 ID와 시도 순번을 복합 기본키로 두고 검사 테이블을 참조한다. [MySQL InnoDB 트랜잭션](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)

검사 행은 입력 식별자와 원본 경로·SHA-256, 설정 해시, 알고리즘·데이터 버전, 최종 판정, 사유와 생성 시각을 담는다. 시도 행은 순번, 분석 단계, 점수, 단계 판정, 사유와 소요 시간을 담는다. 계산되지 않은 점수는 NULL로 보존한다. 원본 영상은 파일 경로와 해시로 연결한다.

## 저장 계약

- 새 ID 쌍은 한 트랜잭션에서 삽입하고 커밋 성공 확인 뒤 저장을 완료한다.
- 중복 키가 발생하면 트랜잭션을 롤백한 뒤 새 조회로 두 ID의 기존 기록을 확인한다. 두 ID가 같은 기존 검사 행을 가리키고, 사용자가 보낸 검사·시도 필드가 모두 같으면 기존 결과를 돌려준다. DB가 생성하는 시각은 이 비교에서 제외한다.
- 두 ID가 다른 행을 가리키거나 저장 내용이 다르면 충돌을 알린다. 기존 행을 덮어쓰지 않는다.
- 연결이 끊기면 실패를 드러낸다. 커밋을 요청한 뒤 응답을 잃은 경우에는 저장 여부를 확인할 수 없음을 표시한다. 계산된 판정과 ID를 재전송에 그대로 사용한다.
- MySQL이 필드 잘림 등 쓰기 경고를 반환하면 전체 저장을 롤백한다. 재전송 비교에 사용하는 내용을 최초 요청과 동일하게 보존한다.

## 영향과 검증

저장 모듈이 연결과 트랜잭션의 수명을 관리한다. C++ 어댑터는 MySQL C API의 준비된 문을 사용한다. 환경 변수에서 접속 설정을 읽고, 스키마 초기화는 관리자 계정으로 수행한다. 시연 계정은 SELECT와 INSERT 권한을 사용한다. 검증한 클라이언트 조합과 절차는 [S05 기록](../steps/S05-storage-history.md)에 있다. [MySQL C API 준비된 문](https://dev.mysql.com/doc/c-api/8.4/en/c-api-prepared-statement-interface.html)

클라이언트 라이브러리는 첫 접속 전에 프로세스에서 한 번 초기화하고, 각 사용 스레드의 자원을 스레드 종료 시 반환한다. 원격 접속은 지정한 CA와 인증서의 서버 이름 검증을 요구한다. 전용 루프백 테스트는 인증서를 지정하지 않고 실행할 수 있다.
