# ADR 0006 가상 장비 TCP 요청과 재전송

- 상태는 승인이다. 사용자가 S06 계획과 ADR 제안을 본 뒤 S06 실행을 요청했다.
- 관련 단계는 S06이다.
- 관련 요구사항은 F08이다.
- Windows ARM64 Release에서 코덱 검사와 루프백 시연을 검증했다.

## 문제와 제약

가상 장비가 등록된 입력을 선택해 검사 요청을 보내고, 응답을 받지 못했을 때 같은 요청을 안전하게 다시 보낼 수 있어야 한다. TCP는 순서가 보장되는 바이트 스트림을 제공한다. 메시지 경계와 시간 제한은 응용에서 정한다. [PRD](https://chatgpt.com/space/page_b35b9c74caac81918226ccdc9e38769e) · [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.7)

## 대안

| 대안 | 적합성 |
|---|---|
| LF 구분 ASCII와 고정 필드 | 콘솔 출력으로 읽을 수 있고 현재 요청과 응답을 구분하기에 충분하다. 값의 문자 집합과 크기를 제한해야 한다. |
| 길이 접두사와 JSON | 가변 필드와 확장에 적합하다. 지금은 길이 헤더, JSON 파서와 타입 검증이 추가된다. |
| 요청마다 새 연결 | 연결 종료로 경계를 잡을 수 있다. 같은 연결에서 이어 붙은 요청을 처리할 수 없고, 매 요청에 연결 비용이 든다. |

## 결정과 이유

Windows C++ 검사 콘솔은 `127.0.0.1`에서 Winsock TCP 서버로 동작한다. Python 표준 라이브러리로 만든 가상 장비가 요청을 보내고 결과를 읽는다. 서버는 연결 하나에서 프레임을 순서대로 처리하며, 연결이 닫히면 다음 연결을 받는다. 비차단 Winsock 소켓과 단조 시계로 수신·송신 마감을 관리한다. 프레임·응답 형식과 시간 제한은 [S06 기록](../steps/S06-device-communication.md)을 따른다. [Winsock recv](https://learn.microsoft.com/en-us/windows/win32/api/winsock/nf-winsock-recv) · [Winsock send](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-send)

완료된 요청은 프로세스 메모리에 최대 256개 보관한다. 같은 `request_id`, `source_id`, `config_id`에 기존 응답을 그대로 돌려주며, 입력 또는 설정 변경은 충돌로 처리한다. 응답을 보내기 전에 결과를 보관하므로 전송 실패 뒤 재연결해도 같은 결과를 받을 수 있다. 한도가 차면 새 요청은 `CAPACITY`를 반환한다. 저장된 요청의 재전송은 한도에 도달한 뒤에도 처리한다.

## 영향과 검증

전송 결과와 샘플 판정을 별도로 표시한다. `config_id`는 등록된 설정의 식별자이고 S05의 설정 SHA-256과 연결하는 처리는 S10에서 맡는다. `inspection_id`의 동일성은 S06 서버 프로세스 수명 동안 검증한다. S10은 실제 검사, 진행 중 요청 상태, 저장 완료 뒤 재전송과 큐 포화를 담당한다.

프레임 분할·병합·상한, 수신·송신 타임아웃, 재연결, 중복 요청, ID 충돌과 보관 한도의 시연 결과는 [S06 기록](../steps/S06-device-communication.md)에 있다. 다른 호스트에서 접속해야 하거나 실제 장비 프로토콜과 연결할 때는 전송 보안, 버전 협상, 영속 재전송 계약을 재검토한다.
