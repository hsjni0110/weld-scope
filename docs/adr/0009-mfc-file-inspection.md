# ADR 0009 MFC 파일 검사와 작업 수명

- 상태: 승인
- 날짜: 2026-11-20
- 관련 단계: S09
- 관련 요구사항: F01, F02, F06, F10
- 승인 근거: 사용자가 S09 실행 계획을 승인하고 구현을 요청했다.
- 구현 검증: ARM64 Release·Debug 실제 MFC 검사와 단일 작업 경계 검증. [S09 단계 기록](../steps/S09-file-inspection-integration.md)

## 문제와 제약

MFC에서 사용자가 선택한 파일을 검사한다. CLI와 같은 검증 및 판정 경계를 유지하고, 취소한 파일의 결과가 다른 원본이나 이력에 연결되는 일을 방지한다.

## 대안

| 방식 | 고려 사항 |
|---|---|
| MFC에서 공용 코드 직접 호출 | 기존 프로젝트와 메모리 내 결과 전달을 유지할 수 있다. |
| CLI 자식 프로세스 | 실행 파일은 재사용하지만 프로세스·임시 출력·취소를 별도로 관리해야 한다. |
| MFC의 CMake 이전 | 링크 구성을 통합할 수 있으며 IDE와 리소스 빌드 이관도 필요하다. |

## 결정과 이유

MFC는 백그라운드 작업에서 S04의 공용 입력 검증, 설정, 엔진과 오버레이를 호출한다. 한 슬롯에서 현재 작업 하나를 실행하고 대기 작업은 수락하지 않는다. UI 스레드가 작업 ID를 검증한 뒤 결과를 화면과 이력에 적용한다. 취소는 즉시 결과 수락을 중단하고 오래 걸리는 호출의 반환 뒤에 슬롯을 회수한다. 창 종료도 같은 회수 경로를 사용한다.

## 영향과 검증

작업 실행은 MFC 컨트롤의 수명 및 UI 메시지와 분리된다. 승인된 초동 입력은 단일 로컬 PNG다. 실제 화면의 결과를 CLI와 대조하고, 제어된 작업 완료로 교체·취소·종료의 경계를 검증한다. 장비와 영구 이력은 S10, 선택적 정밀 분석은 S11에서 연결한다.
