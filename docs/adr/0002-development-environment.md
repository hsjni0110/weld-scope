# ADR 0002 Windows ARM 가상머신 개발 환경

- 상태: 승인
- 날짜: 2026-11-16
- 관련 단계: S01
- 승인 근거: 사용자의 “UTM이 이미 깔려있으니, UTM을 쓰도록 하자”
- 구현 검증: UTM 설치는 사용자 확인. UTM 버전, Windows 설치, 빌드와 실행은 미검증

## 문제와 제약

개발 장비는 MacBook Air M3, 메모리 16GB다. 별도 Windows PC가 없다. 포트폴리오에는 실제 MFC 빌드와 실행이 필요하다. 사용자는 체험판 이용을 원하지 않으며, 이미 설치된 UTM을 사용하기로 결정했다.

## 대안

| 대안 | 고려 사항 |
|---|---|
| UTM과 Windows 11 ARM | 이미 설치된 도구 활용, 사용자가 선택한 환경 |
| VMware Fusion Pro와 Windows 11 ARM | 기존 선택이었으나 별도 설치가 필요해 UTM으로 변경 |
| Parallels와 Windows 11 ARM | 안내형 설치, 체험 이후 비용에 대한 사용자 선호와 불일치 |
| 별도 또는 원격 Windows PC | 추가 장비나 원격 환경 확보 필요 |
| Mac만 사용 | 공용 엔진 개발 가능, 최종 MFC 검증 충족 불가 |

## 결정과 이유

UTM 안의 Windows 11 ARM에서 Visual Studio를 사용한다. 초기 C++·OpenCV·MFC 개발 환경을 하나로 통일해 환경 간 차이를 줄인다. 화면과 검사 엔진의 코드는 분리한다.

메모리 8GB, CPU 4코어는 시작 설정 제안이며 확정된 성능 요구사항이 아니다. 남은 저장공간, 설치 버전, 대상 바이너리 아키텍처와 라이브러리 조합은 S01에서 확인한다. Windows 인증 여부를 빌드 호환성 검증 결과와 혼동하지 않는다.

기존 ADR 0001의 VMware Fusion 선택을 대체한다. 기존 Windows ARM·Visual Studio·MFC 개발 방향은 유지하고 가상화 도구만 변경한다. UTM의 실제 버전과 사용 가능한 Windows ARM 구성은 S01에서 확인한다.

## 영향과 검증

S01에서 MFC 창의 생성과 OpenCV 이미지 표시를 실제로 확인한다. 같은 빌드 대상에 맞는 의존성을 사용하고 MySQL 클라이언트 연결은 S05에서 검증한다. ARM64와 x64를 동시에 지원하는 범위를 미리 확정하지 않는다.

가상머신의 처리시간은 하드웨어, 할당 자원, Windows 버전, 대상 아키텍처와 함께 기록한다. 물리적 x64 검사 장비의 성능으로 일반화하지 않는다.

## 재검토 조건

필요한 의존성의 빌드·실행이 성립하지 않거나 메모리·디스크 제약으로 검수 시연이 어려우면 원격 Windows 등 대안을 다시 검수한다. macOS에서의 엔진 실행 추가는 별도 필요가 생길 때 결정한다.
