# ADR 0003 OPENZDM 데이터 준비와 공식 분할 보존

- 상태: 승인
- 날짜: 2026-11-17
- 관련 단계: S02
- 관련 요구사항: F01, F09와 후속 평가의 재현성
- 승인 근거: Python 선택 후 2026-11-17 사용자가 설계 및 ADR에 “승인할테니 진행”으로 승인
- 구현 검증: 준비 도구의 합성 입력 자동 검사 수행. 실제 데이터 전체 검산은 [S02 결과](../steps/S02-data-preparation.md) 참조

## 문제와 제약

공개 데이터의 사용 조건, 입력 무결성, 분할 간 누수를 확인해야 후속 검사 결과를 해석할 수 있다. PRD는 OPENZDM을 주 데이터 방향으로 지정했지만 실제 파일 구성을 검산하지 않았다. 부품 그룹 ID와 픽셀 정답은 확인되지 않았다.

## 대안

| 대안 | 고려 사항 |
|---|---|
| 공식 분할 유지와 문제 목록 | 출처와 비교 가능성을 보존. 누수가 있으면 평가 사용 보류 필요. 제안 |
| 파일 단위 무작위 재분할 | 간단하지만 중복·같은 부품의 누수 해결을 보장하지 못함 |
| 부품 단위 재분할 | 독립성 확보에 유리하나 신뢰할 부품 ID가 아직 없음 |

도구 대안은 [S02 설계](../steps/S02-data-preparation.md)의 접근 방식 표를 따른다. 사용자는 Python을 선택하고 Pillow 도입을 포함한 설계를 승인했다. 제품 검사 엔진은 계속 C++로 개발한다.

## 결정과 이유

공식 API에서 CC BY 4.0을 확인한 OPENZDM을 S02 점검 대상으로 채택한다. 라이선스 근거·원본 메타데이터·ZIP 체크섬과 파일별 해시를 기록하고, 공식 분할을 보존한 manifest를 생성한다. 라벨은 원본 OK/KO를 보존한다.

파일 및 픽셀 완전 중복과 유사 후보를 구분한다. 유사 후보는 자동 삭제하지 않는다. 분할 간 중복 또는 라벨 충돌이 있으면 문제를 공개하고 평가 사용을 보류한다. 실제 문제를 근거로 별도 정제 정책을 검수받으며 원본 분할을 조용히 변경하지 않는다. 제품 그룹을 알 수 없으면 제품 단위 독립성은 미검증이다.

## 영향

데이터 준비는 Python 보조 도구로 한정하고 MFC와 제품 엔진에 Python 의존성을 추가하지 않는다. ZIP과 전체 원본은 Git에서 제외하고 공개 산출물에는 출처·라이선스·가공 여부를 표시한다. train 샘플만 접촉표에 사용한다. 후속 단계는 manifest와 점검 제한을 함께 인계받는다.

## 검증

[S02 설계의 수락 기준](../steps/S02-data-preparation.md#수락-기준과-검증)에 따라 원본 체크섬, 전체 파일 수·클래스 수, 디코딩, 중복과 오류, 재실행 결정성을 검증한다. 공식 설명과 로컬 검산 결과를 구분하며 데이터 준비 성공을 검사 정확도 성과로 보고하지 않는다.

## 재검토 조건

실제 전체 점검에서 RGB 저장과 다양한 크기, 분할 간 유사 후보가 확인됐다. 이는 원본을 변경하는 근거로 사용하지 않으며 [S02 결과의 제한](../steps/S02-data-preparation.md#검증과-남은-제한)으로 공개한다. 후속 평가 사용 정책은 사용자 검수 대상이다. 이용 조건 변경, 확정 누수·라벨 충돌·부품 그룹 정보가 발견되면 사용 범위와 정제 분할 정책을 다시 검수한다. Pillow 설치가 다른 실행 환경에서 성립하지 않으면 검증 가능한 버전 또는 대안을 제안한다.
