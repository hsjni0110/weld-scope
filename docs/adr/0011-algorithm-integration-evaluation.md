# ADR 0011 공용 검사 호출과 S11 평가 기준

- 상태는 승인이다. 사용자가 S11 실행 계획을 승인하고 구현을 요청했다.
- 관련 단계는 [S11](../steps/S11-algorithm-integration-evaluation.md)이다.
- 이 문서의 로컬 기본값은 S11 당시의 선택이다. 현재 포트폴리오 앱의 기본값과 이전 장비 요청 호환 범위는 [ADR 0014](0014-lightgbm-only-inspection.md)을 따른다.
- 관련 요구사항은 F02, F03, F04, F05, F09다.
- [ADR 0003의 평가 보류 조건](0003-dataset-preparation.md#재검토-조건)에 따라 S11의 데이터 사용 범위를 이 문서에서 확정한다.

## 문제와 대안

CLI와 MFC가 같은 입력에서 같은 단계·판정·사유를 만들어야 한다. 정책 확정에는 검증 집합만 사용해야 하며, 시험 비교에서는 분할 간 유사 후보가 결론에 미치는 영향을 드러내야 한다.

| 결정 | 제안 | 대안과 영향 |
|---|---|---|
| 검사 연결 | 네 경로를 기존 엔진과 정책으로 조합하는 공용 C++ 호출 | CLI와 MFC의 개별 연결은 분기가 적어 보이지만 취소, 시간 경계, 점수와 버전 계약이 갈라질 수 있다. |
| 데이터 | 교차 분할 유사 그룹을 제외한 검증·시험 집합과 공식 전체 비교 | 공식 분할만 보고하면 알려진 유사성의 영향을 확인하기 어렵다. 무작위 재분할에는 부품 그룹 근거가 부족하다. |

## 작업과 호환성

- 공용 결과에 판정, 정책 사유, 단계별 관측과 후보 마스크를 둔다. CLI와 MFC는 각각 출력만 적용한다. 정밀 분석 진입 이벤트는 화면 진행에 사용하고 최종 판단과 단계 시도는 기존 MySQL 상태 값으로 표현한다. 시간 초과로 최종 REVIEW를 반환할 때도 실행한 단계와 측정값을 보존한다.
- 로컬 파일의 운영 경로는 동결한 선택적 설정을 사용한다. TCP의 `selective-v1`은 S11 검증에서 동결한 설정 해시에 고정한다. 기존 `baseline-v1`과 이전 요청의 재전송 계약을 유지한다. 설정이 없거나 다른 해시일 때도 기존 요청은 고정 해시로 재조회한다. 다른 설정으로 장비의 새 요청을 받으려면 별도 등록 ID가 필요하다. 기존 검사와 분석 시도 테이블을 사용한다. [동결 기록](../steps/S11-evidence/freeze.json) · [ADR 0010](0010-record-device-integration.md)
- OPENZDM의 공식 행과 분할을 보존한다. 기존 S02 dHash 목록에서 같은 해시와 해밍 거리 5 이하 관계를 연결한 뒤, 연결 그룹이 두 분할 이상에 걸치는 검증·시험 행을 주 평가에서 제외한다. S07이 이미 사용한 전체 train과도 대조한다. 원본의 동일 부품 여부를 확인할 ID는 없다. 주 평가 결과에도 이 한계를 명시하고, 공식 시험 전체 결과는 유사 후보 제외에 따른 민감도 비교로 표시한다.

## 동결과 측정

1. 주 검증 집합에서 S04·S07 특징 계산 설정을 고정하고 빠른·정밀 점수와 각각의 분석 시간을 짝으로 얻는다. 시간 예산 제안은 검증 집합에서 측정한 짝별 합산 분석 시간의 최근접 순위 p95를 마이크로초 단위로 올림한 값이다. 유효 쌍 수와 적용 환경을 기록한다.
2. 각 단계의 후보 경계는 검증 점수 십분위와 0·1의 중복 제거 집합에서 고른다. 십분위는 최근접 순위를 사용한다. S08의 등호 규칙과 `passMax < failMin` 조건을 적용한다. C++ 정책에 고정 관측을 전달해 후보별 집계를 얻는다.
3. 제약은 주 검증 집합에서 S04보다 많은 KO 자동 통과 금지, 전체 자동 판정률 90% 이상, 정밀 호출률 25% 이하다. 오류와 보류는 자동 판정 건수에서 제외한다. 고정 관측에서 제약을 충족한 후보를 OK→FAIL 수, KO→PASS 수, 정밀 호출 수, REVIEW 수가 작은 순으로 정렬한다. 동률이면 빠른 PASS 경계, 빠른 FAIL 경계, 정밀 PASS 경계, 정밀 FAIL 경계 순으로 작은 값을 선택한다. 예산을 유지하고 그 순서대로 재실행해 실측에서도 처음으로 제약을 충족한 후보를 채택한다. 충족 후보가 없으면 검증 결과와 제약을 검수하고 시험을 보류한다.
4. 정책, 경로별 설정·버전, 데이터·제외 manifest·실행 파일 해시와 VM 조건을 시험 전에 동결한다. 네 경로를 동일 시험 행에 적용하고 보고 집합은 같은 결과 행에서 계산한다. 시간 예산 판정은 호출이 반환된 뒤 S08 방식으로 확인한다. 반복 간 시간 변동과 그로 인해 바뀐 보류 건수를 공개한다. [ADR 0008](0008-selective-inspection-policy.md)

## 검증과 재검토 조건

동결 기록 없이 시험 실행을 요청하는 경로를 거절하는지 검사한다. S07·S08·S10의 기존 회귀 검사와 실제 파일·TCP·MySQL 검수로 결과와 단계 순서를 대조한다. 다른 하드웨어로 시간 예산을 옮기거나, 새 유사 후보 기준 또는 재설정한 정책으로 시험 결과를 보고할 때는 별도 평가 식별자와 근거를 남긴다.
