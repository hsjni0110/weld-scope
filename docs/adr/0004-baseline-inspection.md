# ADR 0004 C++ 기준 검사와 train 개발 실행

- 상태: 승인
- 날짜: 2026-11-18
- 관련 단계: S04
- 관련 요구사항: F01, F02, F03, F09
- 승인 근거: 2026-11-18 사용자가 S04 계획과 ADR 제안 설명 후 “진행해.”로 실행 승인. train 개발 전용 범위이며 독립 평가 사용 보류는 유지한다.
- 구현 검증: ARM64 OpenCV 4.13.0과 C++ 검사 실행. train 43,169장 2회, 시간 외 결과와 64개 중간 PNG 일치. 상세 증거는 S04 기록 참조.

## 문제와 제약

S03은 MFC의 사전 지정 샘플 화면이다. 실제 검사 결과를 만드는 C++ 기준과 UI 밖에서 재현할 실행 경계가 필요하다. 현재 프로젝트의 OpenCV 연결은 확인되지 않았으며 ARM64 빌드가 선행돼야 한다.

S02는 RGB와 다양한 크기, 분할 간 유사 후보와 제품 그룹 미확인으로 `evaluation_ready=false`다. 기준 실행을 진행하면서 이 제한을 없어진 것으로 취급해서는 안 된다. 원본과 공식 분할을 보존하는 ADR 0003은 유지한다.

## 대안

| 대안 | 장점 | 비용과 제안 |
|---|---|---|
| OpenCV 기본 연산을 쓰는 엔진과 별도 CLI | 표준 연산과 파일 저장 재사용, UI 없는 검사 가능 | ARM64 연결 검증 필요. 추천 |
| Windows 디코더와 직접 영상 연산 | OpenCV 의존성 생략 | 별도 디코딩·연산·출력 구현과 검증 부담 |
| MFC 이벤트에서 바로 계산 | 시연 연결이 빠름 | 엔진 재사용·독립 검증이 어려워짐. 미선택 |
| 평가 정책 확정까지 모든 실행 대기 | 평가 주장 혼동 방지 | 제한을 명시한 train 개발 기준까지 중단됨 |

## 결정과 이유

1. S04의 기준은 [전역 어두운 픽셀 비율](../algorithms/global-dark-ratio.md)로 정한다. 국소 특징과 학습 모델은 추가하지 않는다.
2. 영상과 설정을 받는 작은 엔진을 CLI와 검사 실행 파일이 사용한다. CMake와 OpenCV 기본 모듈을 재사용하고 MFC·DB·소켓·Python에 대한 엔진 의존성은 두지 않는다. MFC 연결은 S09에서 수행한다.
3. 실제 RGB·가변 크기는 유효 입력으로 수용하되 원본을 덮어쓰거나 공통 크기로 변환하지 않는다. train만 개발 실행과 설정 선택에 사용한다. validation/test 성능 평가, 자동 후보 제거와 재분할은 승인하지 않는다.
4. 현재 S04 결과는 PASS·FAIL·ERROR로 구분하고 ERROR에 가짜 점수를 넣지 않는다. REVIEW 정책과 공통 작업·저장·전송 상태는 담당 단계에서 결정한다. S03의 SampleSession이나 사전 지정 판정을 제품 엔진 계약으로 재사용하지 않는다.
5. 설정·입력의 식별 정보, 오류, 단계 시간과 중간 영상을 남긴다. 라벨은 보고서 집계에만 결합하며 실제 판정 함수의 입력으로 사용하지 않는다.

## 영향

실행과 검증의 범위·파일 책임·CLI·수락 기준은 [S04 기록](../steps/S04-baseline-inspection.md)을 따른다. 로컬 원본과 대량 산출물은 Git에서 제외하고 소수의 검수 증거와 사용 조건을 문서에 남긴다. train 개발 통계는 독립 성능이나 누수 해결 증거가 아니다. OpenCV 4.13.0 소스 체크섬, ARM64 Release 정적 라이브러리와 `/MD` 런타임 구성을 실제 연결 검증 후 고정했다. 제품 설정과 의존성 설정의 기준은 해당 JSON·빌드 스크립트다.

## 검증

ARM64 실제 PNG 읽기·쓰기, 손으로 계산한 픽셀 수와 판정 경계, 오류 입력·설정·출력 실패, 단일/일괄/재실행 일치, 원본 해시와 train 결과 수를 확인한다. 기존 S02·S03 검사를 함께 수행하고 실제 결과 그림과 크기별 측정을 제시한다.

## 재검토 조건

ARM64 연결이 성립하지 않거나 필수 의존성 범위가 크게 늘면 경로를 재검수한다. 실제 입력에서 전역 밝기 기준의 한계가 드러나면 해당 실패를 S07의 근거로 남긴다. 부품 그룹 정보나 확정 누수·라벨 오류가 발견되면 별도 평가 정책을 검수한다. S04 개발 통계를 최종 성능으로 승격하지 않는다.
