# WeldScope 개발 로드맵

개괄 계획이며 구현을 일괄 승인하는 문서가 아니다. 사용자는 각 단계의 결과를 검수한 뒤 다음 진행 범위를 정한다. 현재 S01을 진행 중이며 나머지 단계는 미착수다. 방향 선택이나 문서 작성은 구현 완료로 계산하지 않는다.

## 단계 운영

- 단계 시작 시 목표, 변경 범위, 실행 방법, 눈으로 확인할 결과, 수락 기준을 짧게 구체화한다.
- 설치와 구성 작업은 실제 창 또는 실행 결과를 만드는 단계에 포함한다. 기반 코드만 만들고 끝내지 않는다.
- 번호는 식별자다. 표의 선행 조건을 만족하면 서로 독립적인 가지는 순서를 바꿀 수 있다. 동시 작업이나 에이전트 위임을 자동 승인하지 않는다.
- 검수 결과는 승인, 수정 요청, 보류 중 하나로 기록한다. 승인을 예상하여 다음 단계 기능을 구현하지 않는다.
- 샘플을 사용하는 단계는 고정 fixture와 실행 명령을 제공한다. 시연 화면에 “샘플”을 표시하고 실제 검사 성능과 구분한다.
- 단계 완료 보고에는 실행 명령 또는 조작 순서, 실제 관찰 결과, 변경 ADR, 남은 제약, 사용자 확인 항목을 포함한다.

S02는 Mac에서 수행할 수 있다. S05와 S06은 먼저 간단한 샘플 결과 계약을 사용하되 도메인 상태 이름을 따로 만들지 않는다. 결과 계약이 달라지면 관련 시연 fixture도 같은 변경에서 갱신한다.

S09에서 이미 실제 파일 검사를 볼 수 있으며, S10에서는 기준 알고리즘만으로 전체 장비 흐름이 동작한다. S11까지 모든 결과가 보류되는 긴 통합 대기를 만들지 않는다. 최종 통합에서 문제가 생기면 각 독립 시연으로 되돌아가 원인을 좁힌다.

## 평가와 결정 시점

- S02: 데이터 사용 조건과 분할 위험 확인. 실제 데이터 이용 조건 미확인 시 주 데이터 채택 보류.
- S04: 기준 실행 측정 후 평가 분모, 시간 측정 경계, 목표 수치 제안과 사용자 검수.
- S07: 특징과 정밀 분석 방식 선택. 시험 세트는 개선 방향 탐색에 사용하지 않는다.
- S08: 정책 계약 검수. 샘플 통과는 정확도 개선 증거가 아니다.
- S11: 검증 세트로 임계값을 고정하고 시험 세트 최종 평가. 결과를 보고 임계값을 다시 고치면 새로운 평가 절차를 기록한다.
