# S02 구현 계획

> 실행 방식: 승인된 설계를 이 세션에서 직접 구현한다. Superpowers executing-plans, test-driven-development, verification-before-completion을 적용한다.

**목표:** 공식 OPENZDM 파일을 검산하고 고정 manifest, 중복 보고서, train 접촉표를 재생성한다.
**구성:** Python 표준 라이브러리와 Pillow를 쓰는 `tools/prepare_openzdm.py`, `tests/test_prepare_openzdm.py`, `tools/requirements-s02.txt`. 기존 MFC 프로젝트는 보존한다.
**설계:** [S02](S02-data-preparation.md), [ADR 0003](../adr/0003-dataset-preparation.md).

## 공통 제약과 검토 초점

- 공식 분할과 OK/KO 보존. 삭제·재분할 금지. test는 무결성·누수 점검에만 사용.
- 실제 데이터와 합성 검증 결과 구분. manifest는 실행 시각 없이 정렬, 오류 입력도 기록.
- ZIP 경로 이탈, Windows 경로 충돌, 큰 항목 및 손상 이미지에서 조용한 성공 금지.
- 파일 해시와 픽셀 해시 구분. 유사 후보는 확정 중복과 구분.
- 기존 파일 덮어쓰기 금지, 다운로드 실패 시 부분 파일을 완료 원본으로 취급하지 않음.
- 접촉표는 train OK/KO 각 8장, 원본 종횡비, 명시적 라벨, 식별자, 출처와 가공 여부 표시.

## 실행 기록

- 설계 및 ADR 승인: 2026-11-17 사용자 “승인할테니 진행”.
- 기존 상태: 문서 변경, 미추적 MFC 프로젝트와 솔루션이 존재. 변경 전 Python 테스트나 Python 실행 환경 없음.
- 판단: 재승인 없이 이 세션에서 직접 실행. 별도 worktree에 미커밋 사용자 파일을 복사하지 않고 `s02-data-preparation` 브랜치에서 작업. 기존 파일은 그대로 보존하며 자동 커밋·병합하지 않음.
- 판단: Windows의 Python 실행 별칭 대신 프로젝트 내부 공식 CPython embeddable 환경 사용. 일반 재현 절차는 Python venv를 제공하고 이번 실행 환경은 별도로 명시.
- 실제 ZIP 목록: `train`, `val`, `test`. 원본 경로를 보존하고 `val`을 manifest의 `validation`으로 매핑하는 회귀 검사 추가.
- 판단: 최초 실제 train 이미지가 414×40 RGB로 공식 설명과 다름. 정상 디코딩한 원본을 임의 변환·손상 처리하지 않고 원래 속성과 설명 차이를 보고. 픽셀 중복 비교에만 크기 포함 canonical RGBA 바이트 사용. 16MP 디코딩 한도 유지. 잘못된 판단이면 예상과 다른 데이터를 평가에 섞을 수 있으므로 설명 차이를 평가 보류 사유에 추가.
- 독립 검토: `review_s02`가 13개 자동 검사를 재실행하고 전체 신규 도구를 읽음. 빈 `.part` 재개 실패와 거대 PNG 예외의 감사 중단을 재현함.
- 수정: 빈 부분 파일 재개와 서버의 Range 무시를 실제 로컬 HTTP 서버로 검증. 거대 PNG 뒤의 정상 항목까지 감사되는 회귀 검사 추가. 각각 실패를 확인한 뒤 수정, 전체 14개 통과.
- 검토에서 유보한 실제 수량·시각 품질·증거 문서: 전체 실행 후 직접 확인. test dHash는 승인된 누수 점검으로 한정. 평가 보류 시 종료 코드 0은 감사 실행 완료만 의미하며 평가 승인 아님. 해시 입력은 생성된 64비트 값으로 한정. MFC는 범위 밖 보존.
- 실제 결과: 61,670장 전부 디코딩, 공식 분할 수량 일치, 파일/픽셀 완전 중복 및 그 라벨 충돌 없음. RGB 저장, 가로 48–651/세로 22–70픽셀, 3,355종 속성 조합. 유사 후보 전체 33,253쌍과 분할 간 15,032쌍을 보고하고 평가 보류 유지.
- 재현: 2회 전체 감사의 고정 파일 7종 바이트 일치. 실행 시각과 소요시간 외 요약 일치. 두 열 16장 접촉표를 실제 열어 확인. `.tools`, 원본 ZIP과 `artifacts`의 Git 제외 확인.

## 유지보수 리뷰 개선

사용자 요청: 리뷰의 네 항목 전부 개선. 단계와 데이터·평가 분할 정책은 유지한다.

- [x] 글꼴 실패에도 데이터 감사와 요약을 보존. manifest에서 접촉표만 재생성하는 `--contact-sheet-only` 경로 추가. 기존 출력 덮어쓰기 금지 유지.
- [x] 그룹 내부·그룹 간·분할 간 유사 후보 수를 손으로 계산한 fixture로 검증. 고의로 잘못된 집계를 반환할 때 테스트 실패 확인.
- [x] 중복 그룹, 샘플 선택, 요약과 보류 조건의 중첩 표현식을 명시적 집계와 조건문으로 정리. 불필요한 클래스나 파일 추가 없음.
- [x] 다운로드 함수가 검증된 SHA-256을 반환하고 CLI가 재사용. 새 다운로드·기존 파일·명시적 ZIP 경로의 중복 읽기 방지 검증.
- [x] 자동 검사, 공식 원본 61,670장 재실행, 기존 고정 산출물과 비교, 증거·문서 갱신.

실패 확인: 기존 14개 검사에 회귀 검증을 추가한 17개 실행에서 글꼴 실패, 접촉표 분리 API 미구현, SHA 반환 누락과 CLI 중복 해시를 확인했다. 기존 유사도 집계는 손계산 fixture의 전체 10쌍/분할 간 8쌍과 일치했으며, 이 검사는 향후 회귀를 보호한다.

최종 검증: 19개 자동 검사 통과. 고의로 후보 수를 -1로 반환하면 새 집계 검사가 실패한다. 공식 61,670장 재실행에서 고정 파일 7종의 해시와 시각·소요시간 외 요약이 기존 증거와 일치한다. 실제 접촉표 단독 실행도 감사 파일을 바꾸지 않고 같은 PNG·선택 목록을 생성했다. 데이터 감사와 시각화, 순수 요약 집계를 분리하고 다운로드의 검증된 SHA-256을 재사용했다. 상세 비교는 [유지보수 개선 검증](S02-evidence/maintenance-verification.json) 참조.

검토 제한: 작성자가 변경 흐름과 회귀 검증을 확인했다. 별도 검토자의 재검토는 소스 읽기 명령이 끝나지 않아 중단했으며, 독립 확인 완료로 계산하지 않는다. 최초 구현의 독립 검토와 이번 재검토 시도를 구분한다.
