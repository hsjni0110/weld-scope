# 엔지니어링 원칙

## 책임과 OOP

OOP 원칙을 모든 코드 설계와 검토에 적용한다. 상태와 그 상태의 불변식을 같은 객체에서 관리하고, 호출자가 내부 순서와 자료구조를 알아야 하는 인터페이스를 줄인다.

| 원칙 | 적용 기준 |
|---|---|
| 캡슐화 | 유효하지 않은 상태의 생성을 막고 상태 변경 경로를 제한한다. 공개 필드 대신 무조건 getter와 setter만 추가하는 방식은 캡슐화로 간주하지 않는다 |
| 단일 책임 | 영상 계산, 판정 정책, 작업 제어, 화면 표시, 저장, 통신의 변경 이유를 분리한다 |
| 개방 폐쇄 | 실제로 필요한 알고리즘 교체와 입력 경로 추가가 호출부의 광범위한 수정 없이 가능하도록 한다 |
| 리스코프 치환 | 구현을 바꿔도 입력 조건, 반환 의미, 오류 계약이 유지되어야 한다 |
| 인터페이스 분리 | 호출자가 사용하지 않는 기능이나 내부 설정을 알 필요 없게 한다 |
| 의존성 역전 | 공용 엔진과 판정 로직이 MFC, MySQL, 소켓 구현에 의존하지 않게 한다 |

합성을 기본으로 사용하고 상속은 실제 치환 관계가 있을 때 사용한다. 수학 계산은 순수 함수와 값 타입으로 표현할 수 있다. 모든 함수를 클래스로 감싸거나 모든 클래스에 추상 기반 클래스를 만드는 방식은 요구하지 않는다.

구체적인 변화 지점 또는 외부 I/O 격리의 필요가 있을 때 인터페이스를 도입한다. 이름만 전달하는 계층, 전역 서비스 로케이터, 미래를 위한 플러그인 프레임워크는 추가하지 않는다.

## 아키텍처

현재 방향은 작은 공개 인터페이스 뒤에 구현 복잡성을 숨기는 모듈이다. 최종 경계와 계약은 해당 단계의 ADR에서 결정한다.

- 영상처리와 판정은 UI 없이 호출하고 검증할 수 있어야 한다.
- UI는 사용자 의도 전달과 결과 표현을 맡는다. 이벤트 핸들러에 알고리즘이나 SQL을 작성하지 않는다.
- 외부 I/O 구현은 별도 어댑터로 격리하고 필요한 의존성을 생성자 또는 명시적 인자로 전달한다.
- 작업 제어는 처리 순서와 취소를 담당한다. 소유권, 작업 수명, 큐 상한, 종료 순서를 명시한다.
- 검사 판정, 작업 상태, 저장 상태, 전송 상태는 구분한다. 저장 실패가 계산된 판정을 덮어쓰지 않는다.
- UI 스레드는 장시간 연산과 DB·네트워크 대기로 차단하지 않는다.
- 요청 ID, 검사 ID, 입력 해시, 알고리즘 설정의 의미는 한 곳에서 정의한다.
- 테스트는 공개 계약과 사용자에게 중요한 동작을 검증한다. 내부 호출 순서만 복제하는 테스트는 피한다.

## C++ 자원과 오류

RAII를 기본으로 파일, 소켓, DB 연결, 메모리, 스레드 수명을 관리한다. 값 소유와 단독 소유를 우선하며 공유 소유는 실제 수명 요구가 있을 때만 사용한다. 비소유 참조의 유효 기간을 명확히 한다.

빈 값, 오류, 취소, 보류를 서로 다른 의미로 표현한다. 오류를 정상 기본값으로 치환하지 않는다. 경계에서 입력 크기와 형식을 검증하고 부분 실패를 호출자가 식별할 수 있게 한다. 변경 가능한 전역 상태를 최소화한다.

## 사람이 읽을 수 있는 코드

- 변수와 함수 이름에 업무 의미를 담는다. 예: inspectionResult, defectScore, reviewThreshold, processingDurationMs.
- 불필요한 축약, data2, tempResult 같은 모호한 이름을 피한다. 짧은 루프 인덱스와 수식의 국소 변수는 문맥이 분명할 때 허용한다.
- bool은 is, has, can 등 질문 형태로 작성한다. 시간·크기·좌표 이름에 단위를 드러낸다.
- 클래스는 책임을 나타내는 명사, 동작 함수는 동사로 이름 짓는다. UI 명사형 규칙을 함수명에 적용하지 않는다.
- 상태와 설정은 enum 및 명명된 값으로 표현한다. 의미 없는 숫자와 문자열을 여러 곳에 복사하지 않는다.
- 한 함수에서 추상화 수준을 맞추고 중첩을 줄인다. 함수 길이 숫자보다 읽기와 책임을 기준으로 분리한다.
- 주석은 의도, 제약, 알고리즘 근거를 설명한다. 코드가 말하는 동작을 그대로 반복하지 않는다.
- 기존 코드가 생긴 뒤에는 하나의 네이밍·포매팅 관례를 일관되게 적용하고 도구 설정으로 고정한다.

## 검증과 검수

변경한 동작과 실패 위험에 맞게 테스트한다. 정밀 분석 경계값, 요청 중복·충돌, 취소, 손상 입력, 시간 초과, 큐 포화, DB 단절은 담당 단계에서 검증한다. UI는 실제 실행 화면에서 확인한다.

단계 완료 전 빌드, 관련 자동 검사, 사용자 시연을 확인한다. 실행하지 못한 검증과 플랫폼은 분리해서 보고한다. 새 빌드 경고를 방치하거나 경고 옵션을 낮춰 해결하지 않는다. 중요한 설계 선택은 [ADR 절차](../adr/README.md)에 따른다.
