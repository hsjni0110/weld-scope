# UI UX 원칙

## 디자인 스킬

화면, 흐름, 레이아웃, 스타일, 상태 표현, 사용자에게 보이는 문구를 만들거나 수정할 때 항상 해당 작업에 적합한 디자인 스킬을 읽고 적용한다. 작업 기록에 적용한 스킬과 검수 결과를 남긴다. 디자인 스킬을 단순히 이름만 언급하고 적용을 생략하지 않는다.

사용 가능한 스킬을 확인하고 MFC 데스크톱 UI에 맞는 설계 원칙을 적용한다. 스킬이 웹 도구를 전제로 하더라도 최종 구현 기술을 임의로 웹이나 Qt로 변경하지 않는다. 적합한 스킬을 사용할 수 없으면 그 제약을 알리고 UI 작업을 보류한다. 독립적인 비 UI 작업은 진행할 수 있다.

## 문구

사용자에게 보이는 제목, 메뉴, 버튼, 상태, 필드는 짧은 명사형으로 통일한다.

| 용도 | 문구 예시 |
|---|---|
| 입력 | 이미지 선택, 폴더 선택 |
| 제어 | 검사 시작, 검사 중지 |
| 상태 | 대기, 검사 중, 완료, 검토 필요 |
| 결과 | 정상, 불량, 처리 오류 |
| 연결 | 연결 상태, 연결 끊김, 재연결 |
| 기록 | 검사 이력, 저장 실패, 저장 재시도 |

중간점(·) 등 장식용 구분자를 UI 문구에 사용하지 않는다. 여러 항목은 실제 레이아웃과 간격으로 구분한다. “중간자”라는 사용자 표현은 이 문서에서 장식용 구분자를 뜻하는 것으로 해석했다. 다른 의미가 확인되면 해당 규칙을 수정한다.

부가 설명은 정확한 판단이나 다음 행동에 필요한 경우에만 사용한다. 당연한 기능을 반복하는 부제, 홍보성 문구, 기술 구현 설명은 화면에 추가하지 않는다. 오류에는 복구에 필요한 원인과 행동을 간단히 제공한다. 예: “DB 연결 끊김”과 “재연결”. 설명이 필요해도 가능한 한 명사형으로 작성한다.

기술 용어와 내부 상태 코드 대신 검사 담당자가 이해할 수 있는 한국어를 사용한다. 실제 데이터가 아닌 시연은 “샘플”로 표시한다. 점수를 검증 없이 확률로 표현하지 않는다.

## 단순한 흐름

기본 흐름은 입력 선택, 검사, 결과 확인, 이력 조회다. 현재 단계에서 필요한 주요 동작을 우선 노출하고 드문 설정은 별도 영역에 둔다. 내부 모듈 구조를 메뉴 구조로 그대로 옮기지 않는다.

원본 영상, 최종 판정, 현재 작업 상태가 쉽게 구분되어야 한다. 색상만으로 정상·불량·보류를 표현하지 않는다. 초점, 키보드 조작, 글자 대비, 창 크기·DPI 변화에서의 잘림을 확인한다.

빈 상태, 로딩, 검사 중, 취소, 오류, 저장 실패, 긴 파일명, 이미지 비율 차이도 설계한다. 연산 중에도 상태 확인과 중지 요청이 가능해야 한다. 점수와 분석 시간의 라벨을 분리한다.

## 시각 검수

UI 단계마다 실제 화면 또는 작동하는 시제품을 제공한다. 표나 설명만으로 UI 완료를 선언하지 않는다. 목업, 샘플 동작, 실제 엔진 연동 상태를 구분한다. 사용자 검수에서 나온 수정은 그 단계에 반영한 뒤 다음 단계로 진행한다.
